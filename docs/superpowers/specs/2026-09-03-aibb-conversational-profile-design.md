# AIbb 对话式出游与资料同步设计

**状态：已由用户确认，待用户审阅本文档后实施。**

## 目标

把 AIbb 从“探索结果卡片”调整为对话里的快乐出游伙伴：用户明确邀请它去玩时，AIbb 才出发；回来后在同一条聊天时间线里写一篇自然、有主观感受、有来源的出游日记。普通问题维持普通模型聊天。

用户可在右键设置中修改 AIbb 昵称并导入本地头像。昵称和头像必须立即同步到桌宠、对话标题、AIbb 消息、出游日记和原生窗口标题。

## 非目标

- 不让 AIbb 自动开始下一轮出游。
- 不把用户头像、用户昵称或 API Key 混入 AIbb 资料。
- 不上传头像、原图路径或聊天内容到额外服务。
- 不允许模型输出的 HTML 直接进入 WebView。

## 用户体验

### 普通聊天

用户发送普通问题时，保持当前流式聊天行为。AIbb 使用已保存的昵称和头像显示消息；它不会因为普通问题自行启动网络探索。

### 出游回合

| 阶段 | 时间线表现 | 后端行为 |
| --- | --- | --- |
| 用户邀请 | 用户消息，如“去玩”“去海里玩” | 只接受现有明确出游意图判定 |
| 出发 | 同一消息下方显示短暂“<昵称> 出发，去玩～”状态 | 创建一次探索任务并开始计时 |
| 探索 | 状态随进度更新，不显示独立结果卡 | 自主或按用户方向寻找 4 个发现 |
| 回来 | 追加一条 AIbb 消息 | 写入一篇完整出游日记并结束计时 |
| 收尾 | 日记自然收束，留下好奇或邀请 | 不触发任何下一次任务 |

出游日记的语气参考用户提供的示例：有“第 N 轮回来”的回归感、路线串联、每一站的惊喜和吐槽、对四站之间联系的收束、AIbb 的私心冠军，以及可信来源。模型保有自由发挥空间；唯一产品约束是研究仍基于恰好 4 个发现，且来源只能来自本次实际获得的安全页面或原生联网来源。

## 对话与探索架构

### 意图分流

`submit_user_input` 继续是唯一输入入口。

- 现有明确出游语句（“去玩”“去某方向玩”等）返回 `explorationStarted`。
- 其他语句返回 `chatStarted`，走原有 ChatService。
- 前端不通过关键词二次猜测；它只依据后端返回的 `InputDisposition` 改变时间线状态。

### 出游报告

探索任务保留已有“4 个发现 + 下一次自然好奇”的可靠结果校验，但完成阶段新增日记合成：

1. 研究阶段产出并校验 4 个发现。
2. 合成阶段把发现、本次安全来源、用户方向、累计成功轮数和实际耗时交给模型。
3. 模型返回纯文本日记与受控来源引用。
4. 后端把日记作为 Assistant 消息写入本地记忆，并在 `exploration://complete` 中发送给聊天窗口。

`ExplorationResult` 将增加受控的 `diary`、`sources`、`roundNumber` 和 `elapsedSeconds` 字段。`sources` 只包含本次获得的标题与安全 canonical URL，前端只将这些受控 URL 渲染为链接；日记正文中的内容仅按纯文本或安全的轻量段落格式显示。

聊天窗口不再挂载 `ExplorationPanel`。它改为把探索中的状态作为 Assistant 临时消息，并在完成事件到来时替换为正式日记。探索失败保留安全中文提示，不显示模型或网页服务的原始文本。

## AIbb 资料

### 持久化

在现有 `app_settings` 单例记录中新增：

- `aibb_name`：非空昵称，默认 `AIbb`；
- `avatar_filename`：应用托管头像的固定安全文件名或空值；
- `profile_version`：每次资料保存时递增，用于跨窗口刷新。

不在 SQLite 中保存 API Key、原图绝对路径或原始大图二进制。

### 本地头像导入

设置页提供文件选择控件，接受 PNG、JPEG 和 WebP，限制导入大小。前端用浏览器 Canvas 居中裁切并缩放成 256×256 的 WebP 字节后，通过受限 IPC 命令保存到应用数据目录的 AIbb 专属头像文件。

保存采用临时文件后原子替换。导入、解码、写入或格式检查失败时保持旧头像和昵称不变。恢复默认头像会删除应用托管头像引用并回到内置机器人图案。

### 同步

保存资料后后端广播 `profile://updated`，负载只含昵称、头像 data URL 或默认头像标记、版本号。桌宠、聊天和设置窗口均监听该事件并立即更新。

- 桌宠：使用自定义头像的圆形裁切版本；
- 聊天头部：昵称与头像同步；
- 历史和新 AIbb 消息：显示当前昵称与当前头像；
- 出游日记：标题和作者使用当前昵称；
- 原生窗口：更新为 `<昵称>` 与 `<昵称> Chat`。

头像用受控 data URL 返回给 WebView，避免将任意本地磁盘路径暴露给前端或授予宽泛文件访问权限。

## 提示与安全边界

出游日记提示只约束事实来源、四项发现、无敏感信息、日记必须从本次证据出发；不预设题材、情绪、笑话、结论或下一站。AIbb 可自行决定路线、喜好和表达方式。

模型不能自行声称浏览了未提供的链接。来源列表由后端实际收集的来源构成。所有模型文本、错误、URL 和头像输入继续经过现有敏感信息与安全 URL 防护。

## 变更范围

- Rust：迁移、资料服务、头像保存命令、窗口标题更新、探索报告合成、事件与契约。
- React：资料设置卡、文件导入与预览、共享头像组件、聊天时间线中的出游状态与日记、受控来源链接。
- 权限：只增加资料相关命令和事件所需的最小窗口权限。
- 测试：资料迁移、原图路径不持久化、头像失败回滚、跨窗口资料事件、普通聊天/出游分流、4 项发现、日记写入记忆、来源白名单、出游耗时和轮数、Enter/Shift+Enter 回归。

## 验收条件

1. 用户说“去玩”后，聊天时间线中出现一次出发状态和一次 AIbb 出游日记；AIbb 不会自行启动下一轮。
2. 普通问题仍产生普通 AIbb 聊天回复。
3. 每篇成功日记对应 4 个发现、真实来源、成功轮数和实际耗时。
4. 昵称和本地头像修改后，所有三个窗口与已显示 AIbb 消息立即同步。
5. 删除或移动用户原始图片后，AIbb 头像仍可显示。
6. 头像导入失败、探索失败和未知错误不泄露 API Key、原路径或提供商内部文案。
