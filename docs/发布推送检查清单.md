# AIbb 发布推送检查清单

> 每次 push / 发版前先看这份清单。沉淀自 0.3.0 发布踩坑（Release 正文全乱码）。

## 一、编码铁律（最重要）

1. **中文经 `pwsh` 命令行传进 git 是安全的**（已自检）：
   - `git commit -m "中文"`、`git tag -a -m "中文"` → GitHub 显示正常。
2. **但 PowerShell `Invoke-RestMethod` 用「字符串」`-Body` 发中文 JSON 会把中文变成 `?`** —— 0.3.0 的 Release 标题/正文就是这么坏的。
3. 修复方法：**显式转 UTF-8 字节 + 声明 charset**，不要直接传字符串：

```powershell
$json = @{ tag_name = "vX.Y.Z"; name = "中文标题"; body = "中文正文" } | ConvertTo-Json
$bytes = [System.Text.Encoding]::UTF8.GetBytes($json)
Invoke-RestMethod -Method Patch -Uri "https://api.github.com/repos/w384/AIbb/releases/<release_id>" `
  -Headers $headers -Body $bytes -ContentType "application/json; charset=utf-8"
```

4. 发布后**必须回读验证**：GET 一次 release，确认 name/body 没有 `?`（ASCII 丢失）或 `æ–°å¢ž`（UTF-8 被当 Latin-1）之类的乱码。

## 二、发版流程（0.3.0 实操模板）

1. **升版本号（4 处保持一致）**：
   - `src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`（改完 Cargo.toml 跑一次 `cargo check` 自动同步）、`package.json`、`src-tauri/tauri.conf.json`。
   - 规则：新功能升 minor（0.2.0 → 0.3.0）；**已有 tag 的版本号绝不重复使用**；v0.2.0 标签已指向旧提交，功能上线必须换新号。
   - 设置页脚注版本号已改为动态读取（`@tauri-apps/api/app`），无需手动改。
2. **提交并合并**：提交到 feature 分支 → `git checkout main && git merge --ff-only feature/xxx` → `git tag -a vX.Y.Z -m "release: AIbb X.Y.Z — <一句话>"`。
3. **全量验证**：`pnpm typecheck` + `pnpm test` + `cargo test --manifest-path src-tauri/Cargo.toml`（用 `*> log; Write-Output "EXIT=$LASTEXITCODE"` 模式看真实退出码）。
4. **打包**：`pnpm tauri build`（后台跑，产物在）：
   - `src-tauri/target/release/bundle/nsis/AIbb_<ver>_x64-setup.exe`（主安装包，简体中文）
   - `src-tauri/target/release/bundle/msi/AIbb_<ver>_x64_zh-CN.msi`
5. **推送**：`git push origin main` + `git push origin vX.Y.Z`（本机凭据管理器可用，直接推；推送失败再让用户手动推）。
6. **建 Release + 传资产**（token 从 `git credential fill` 取，**绝不打印 token**）：
   - `POST https://api.github.com/repos/w384/AIbb/releases`：tag_name / name / body（body 用 UTF-8 字节，见上）。
   - 上传：`POST https://uploads.github.com/repos/w384/AIbb/releases/<id>/assets?name=<文件名>`，`-InFile` 传文件，`Content-Type: application/octet-stream`。
   - 资产按 v0.2.0 惯例：Windows 上传 NSIS exe（+ 可选 MSI）；macOS 是 dmg（需在 Mac 上构建）。
7. **旧版本保留**：GitHub 上 v0.2.0（exe+dmg）、v0.1.2（dmg）及 v0.1.0/v0.1.1 标签原样保留，**不要动、不要覆盖**。

## 三、发布后验证清单

- [ ] Release 页标题/正文无乱码（回读 GET 确认）
- [ ] 安装包资产在列表中，`browser_download_url` 可直接下载
- [ ] 资产字节数与本地产物一致（exe ≈5.6MB、msi ≈9.5MB 量级）
- [ ] 提交信息、标签注解中文正常（`GET /repos/w384/AIbb/commits/<sha>` 回读）
- [ ] 旧版本 Release 与标签未被动过

## 四、常用命令速查

```powershell
# 取 GitHub token（不打印，只在变量里用）
$cred = "protocol=https`nhost=github.com`n`n" | git credential fill 2>$null
$token = ($cred | Where-Object { $_ -like 'password=*' }).Substring(9)
$headers = @{ Authorization = "Bearer $token"; Accept = "application/vnd.github+json" }

# 查现有 Release
Invoke-RestMethod -Uri "https://api.github.com/repos/w384/AIbb/releases" -Headers $headers

# 回读某个 Release 的标题/正文（发布后验证用）
Invoke-RestMethod -Uri "https://api.github.com/repos/w384/AIbb/releases/tags/vX.Y.Z" -Headers $headers

# 更新已发布 Release（乱码修复专用）—— body 必须 UTF-8 字节
Invoke-RestMethod -Method Patch -Uri "https://api.github.com/repos/w384/AIbb/releases/<id>" -Headers $headers -Body $bytes -ContentType "application/json; charset=utf-8"
```

## 五、本次修复记录（2026-09-19）

- v0.3.0 Release 标题/正文中文全变 `?`：原因 `Invoke-RestMethod -Body <字符串>` 对中文 JSON 编码丢失。
